# Glossary and Resources

## Domain Terms

| Term | Definition |
|------|------------|
| **ADR** | Architecture Decision Record, a structured document capturing a technical decision with context, options considered, and rationale |
| **InfoHub** | Per-account knowledge repository containing decisions, risks, actions, architecture artifacts |
| **Risk Register** | Structured log of identified risks with severity, owner, and mitigation status |
| **Decision Log** | Chronological record of technical and business decisions per engagement |
| **Architecture Design** | The structural blueprint: how systems connect, integration patterns, deployment topology, security boundaries, data flows. It defines the "shape" of the system |
| **Solution Design** | Mapping vendor capabilities to customer requirements: which products/features solve which pain points, licensing model, configuration approach, implementation scope. It defines the "fit" of the offering. Architecture design is the technical foundation, solution design is the customer-specific application of it. The SA does both |
| **Specialist** | Domain expert agent (security, search, observability) triggered when complexity thresholds are exceeded |
| **Signal** | Event or keyword pattern detected in content that may indicate a risk, decision, or specialist need |
| **Staleness** | Condition where an artifact exceeds its maximum age without update |
